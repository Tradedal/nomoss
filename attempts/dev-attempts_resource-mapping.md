# Resource mapping

## Problem

ResourceCatalogs cannot yet resolve some nested identities, relationships, and output fields defined across schema branches. Those gaps leave discovered Stripe resources without usable generated bindings.

## Rules / constraints

ResourceCatalogs must discover resources across the full corrected provider source without a manual operation or client list. It must record creation models before it resolves lifecycle behavior and retain unresolved issues on the affected entries. Hints may resolve ambiguity or supply exceptional names and lifecycle decisions, but must not copy property schemas or define entire resource mappings.

Use canonical JSON Schema contracts, JSON Pointer paths, native Effect compilation, and AST emission. Preserve saved output names, identity, dependency resolution, state format, secret retention, and provider behavior. AWS continues through Cloud Control. General import and credential replacement remain separate.

Use small source documents for domain behavior cases and preserve the existing AWS metadata snapshot. Do not add Stripe metadata comparison tests or test-only APIs. Provider acceptance uses production clients and the stack. The [unified tracker](dev-attempts_unified-resource-generation.md) owns managed generation and catalog-wide acceptance; this tracker owns the source-resolution defects below.

Relationship discovery must retain the allowed resource types and mappings needed by the canonical core contract. Generated Stripe schemas accept compatible resource entities at resolved paths. The unified tracker owns core execution and its provider consumers; source resolution here must preserve the metadata they require across the complete catalog, including issues for unresolved targets.

## Completed

- [x] ResourceCatalogs constructs the catalog from creation responses before it resolves saved-identity reads. Entries retain provider names, request and response schema references, and every discovered creation operation. Resolution adds executable bindings or records bindingIssues and retains the resource in either case. StripeClientGenerator preserves unsupported encodings in the same catalog and emits clients and declarations for resolved entries. Catalog modules use provider namespaces so identically named v1 and v2 resources remain distinct. Operation and client allowlists, the manual resource mapping file, duplicated schema payloads, and temporary discovery artifacts remain removed.
- [x] StripeClientGenerator emits separate resource bindings and schema definitions and preserves its public declaration and contract exports. Shared schema imports are added in one AST operation per module. TypeScriptModulePublisher parses, formats, and organizes imports for the complete output in one process; syntax failures preserve existing destinations. Lint validation has a separate public operation, and single-module publication retains its lint check. Generator execution uses NomossTracingLive, with native compilation stages and publication included beneath the command span.
- [x] Generated Stripe resource clients use Effect services and Layers in the application graph. Resource emission requires the discovered catalog and rejects bindings without a discovered input. Before a generated client invokes the provider to create a resource, it validates resolved declaration properties against the provider operation contract. The generator cannot emit a client that accepts provider inputs instead and bypasses the declaration input contract.
- [x] ResourceCatalogs preserves source schemas and identity through Registry, OpenAPI, and native Effect preparation. Named response aliases resolve to their resource, inherited base schemas do not become extra resources, and required fields respect intersections and alternatives. Resource and relationship identities resolve referenced scalar schemas through one public operation. Unsupported output projections and incompatible read parameters prevent executable bindings and remain explicit on the resource. Hints without a discovered candidate and conflicting catalog type names fail preparation. A binding cannot satisfy parameters in different request locations through a shared name. Existing saved output and dispatch names remain compatible.
- [x] AWS resource generation consumes the shared output catalog and exports it beside each of the six current generated declarations. Cloud Control execution retains the full provider model and its opaque Identifier.
- [x] ResourceModel checks observed identity through the registered contract, including older saved records. Reconciliation rejects mapped reads without last-applied identity and checks deleted-customer identity before it removes saved state. Identity regressions remain with ResourceStackLifecycle.
- [x] Stripe resource declarations return ResourceEntity values for relationships and expose applied outputs as ordinary typed properties. The canonical model saves source identities and request mappings without copying source properties. Internal deferred descriptors remain available to the existing AWS input contracts. StripeExampleApps retains complete Product, Price, Portal, Webhook, and export declarations. Output registration uses Effect's structural HashMap keys.
- [x] BillingConfigurationExport has a canonical native Effect input schema and reviewed local source selection. Generation emits its output schema, projection, annotated resolved input, and declaration; the filesystem lifecycle and StripeResources consume those exports. The writer creates destination directories after document validation.
- [x] StripeResources uses generated declarations and output schemas in the shared runtime. ResourcePlanner schedules property dependents after changed sources, and ResourceStackLifecycle resolves their inputs during execution. Unchanged resolved inputs retain the current provider node without another provider request. Price replacement therefore refreshes portal selections and exported application IDs. Reads preserve identity and webhook signing secrets, failed reconciliation preserves state, and teardown failures remain retryable.
- [x] ResourceCatalogs normalizes structural schema children before parents so nullable OpenAPI constraints survive native Effect compilation. Reference and expansion links remain intact, including recursive models and dictionary values.

## Remaining

- [ ] ResourceCatalogs leaves parent parameters and reads that need several identifiers unresolved. Its resolution flow must retain those source-derived values in generated creation inputs and saved read bindings so applications can declare nested resources and read them through their saved identity.
- [ ] ResourceCatalogs output projection rejects a selected field when several source definitions contribute to that field. The projection must retain every contributing constraint and source location so generated outputs accept the composed model without loss of validation.
- [ ] StripeClient cannot encode the request required for file creation. The [client tracker](dev-attempts_shared-client-generator.md) owns transport support. ResourceCatalogs must retain the operation and the reason it cannot execute on the catalog entry until its binding is executable.
